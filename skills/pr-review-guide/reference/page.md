# The page

Read this when the user asks what the page shows or how it behaves, or before changing `page-template.html`. That template holds the whole page: the theme tokens, the layout and the script. `render.py` only fills in the title and one JSON blob, so a change to how the page looks or behaves goes in the template.

- Each section shows its text and file list on the left, sticky, and its file cards on the right. A file split across sections is tagged `part`, and a gap that hides another section's hunks says so and links there.
- Syntax highlighting is highlight.js, chosen by file extension. Bruno's `.bru` files get a small grammar of their own for block names, keys and `{{variables}}`, with scripts and tests highlighted as JavaScript, JSON bodies as JSON and docs as Markdown. Which block a line sits in comes from the whole new file, since a hunk's context rarely reaches the block's opening line.
- Unified or Split, beside the line counts, switches every diff between one column and removed and added lines side by side. The choice is kept in the viewer's browser; below 860px wide the page stays unified.
- A block of code that moved unchanged shows once, where it landed, marked as moved and linked to where it came from; where it was removed it folds into one row that says where it went, with the lines behind Show them. Only the edits around it read as changes.
- The menu beside the layout switch shows part of the change: what is new since the last build (a rebase that only moves code leaves a hunk as it was), or one commit's hunks, found by blaming each line. Commits that own no hunk, such as merges from the base branch, aren't listed. Cards and sections it doesn't touch hide, and hunks of a shown card that it doesn't touch are dimmed. Cards with new hunks are tagged `new`. Commits aren't mapped past 150 files.
- CI annotations, the lint and type errors and warnings a check run pins to a line, show under the line they are about, with the rest listed in the ready check.
- Formatting is hidden unless the viewer asks for it: formatting-only and re-indented lines inside a real hunk show once, in their new form, as context, and the closing "Formatting only" section, which holds whole hunks of formatting, doesn't show. Formatting, beside the layout switch, shows all of it, dimmed and marked `fmt`, with both sides of a re-indented line; the choice is kept in the viewer's browser. Lock and generated files go to "Lock and generated files" at the end, collapsed.
- Notes, not comments, from the `+` beside a line number: each is kept in the viewer's browser as it is typed, shows under its line with Edit and Delete, and is listed in a Your notes panel at the top, so the whole review can be read and changed before it goes anywhere. Send N notes to Claude posts them as one comment sent to Claude through the `comments` capability (the first send asks the viewer's permission), which reaches the session watching the page, and clears them once posted. Without that capability, on a page opened from disk or for a viewer it isn't granted to, there is no Send button and Copy notes is the way back. A comment holds 4 KB, so a long review goes as several parts in one thread, the first sent to Claude and saying how many follow. Copy notes puts the same text on the clipboard to paste into the session instead, which leaves nothing on the page and needs no watching session; copied notes stay, marked, until Clear copied, since the page cannot tell whether they were pasted. The `room` capability's hand-off to the viewer's own Claude is not used: it reaches a Claude beside the page (the desktop app, or claude.ai), not a terminal session, and from a plain browser tab it can start a new claude.ai conversation that has no access to the repository. Notes live in one browser until sent, and survive reloads and republishes there. On a page opened from disk they live in the tab instead, since every local file shares that origin and another one could plant notes there, so closing the tab drops them.
- "Before you mark it ready" sits under the header: size, CI, annotation, what's new and test chips, flagged lines grouped by file and linked to the line (marked `!` in the diff too), CI annotations, where the description and the linked issue disagree with the diff (claims it doesn't bear out with why, asks it doesn't do, and what the description leaves out), the sections with risk notes, the things to try by hand, the suggested split, and last, collapsed, the claims the diff does carry out, each with the sections that do it.
- Reviewed ticks, per file and per section, live in the viewer's browser storage, keyed by the PR and by what each card's hunks change, not where they sit. A rebuild keeps the tick on a card whose hunks are the same and drops it where any changed.
- The colours are tweakcn's Clean Slate theme, with its light primary and muted text a little darker so they reach 4.5:1. A button at the top right cycles through system, light and dark, and is remembered in the viewer's browser.
- The headline count is implementation lines without formatting noise, like Linear's; the `(*)` popover has every category and the total.

On a stack page, a panel at the top lists the layers top first, each with its line count, CI, flags, description mismatches, careful reads and what it does in the stack, beside the issues that only show across the stack. Clicking a layer, or ↑ and ↓ above each one, switches layers in place, and a row under a hunk names what it shares with other layers ("`LoginCard` used further up the stack: #1013 §05") and jumps there.
